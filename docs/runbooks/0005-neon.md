# Runbook: migration 0005 (log entries) on Neon

Migration 0005 adds `log_entries`, backfills it from existing reports and readings, and cannot be reversed. Everything below uses the Neon and Cloud Run web consoles.

1. **Preflight.** In the Neon SQL editor, run `scripts/neon-preflight-0005.sql`. Every `must_be_*` column must show the value in its name. Production on 2026-10-19 gave: 17 pairs, 4 reports alone, 3 readings alone, 2 report notes, 93 audit rows. Re-run if anyone logged since and note the new numbers.
2. **Backup.** Neon keeps only 6 hours of history, so create a branch from the console (Branches, Create branch, from the production branch, current data) named `backup-before-0005`. Keep it until step 6 passes.
3. **Quiet moment.** Deploy when neither user is logging: the old revision may still serve briefly during the rollout.
4. **Deploy.** Merge the PR at the quiet moment, or open GitHub, Actions, Deploy, the latest run, and click **Re-run all jobs**. The `deploy.yml` workflow builds and rolls out the new image, which runs 0005 and the backfill on start. Agents never merge.
5. **Verify.** In the Neon SQL editor, `SELECT count(*) FROM log_entries` must equal pairs + reports alone + readings alone, plus anything logged since (preflight 2026-10-19: 17 + 4 + 3 = 24). Then open Cloud Shell (a terminal in the browser) and run the following, which takes `DATABASE_URL` from Secret Manager into the environment without printing it (infra/README.md, step 10). It must report the chain clean.

   ```bash
   gcloud auth configure-docker europe-west3-docker.pkg.dev --quiet
   IMAGE="$(gcloud run services describe smoke-tracker --region europe-west3 --format='value(spec.template.spec.containers[0].image)')"
   DATABASE_URL="$(gcloud secrets versions access latest --secret=smoke-tracker-database-url)" \
   docker run --rm -e DATABASE_URL "$IMAGE" verify-audit
   ```

6. **Cleanup.** Once the app works for both users, delete the `backup-before-0005` branch.

**Rollback.** 0005 is not reversible. In Neon, restore the production branch from `backup-before-0005` (Restore in the branch menu), then redeploy the previous image from Cloud Run's revisions list. Entries logged after the backup are lost.
